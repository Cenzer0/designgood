# designgood 2.1

Use this skill to build interfaces with a clear point of view, complete interaction states, and a handcrafted sense of origin. For the stricter authored-design protocol, also read `skills/dsngood/SKILL.md`.

## New handcrafted-origin requirement

Before implementation, identify real source material from the product: a user task, domain vocabulary, meaningful object or process, trust signal, and user hesitation. Write an author’s note explaining what the interface is for, what it should feel like, what the visual metaphor comes from, and what it deliberately refuses.

Every primary screen needs one domain-specific content decision, one non-default layout decision, one purposeful signature element, one task-shaped interaction, and one explicit reason for its visual language.

Do not fake human authorship with random rotation, arbitrary asymmetry, paper grain, doodles, fake cursor marks, decorative noise, or meaningless imperfections. Authorship comes from specificity, not randomness.

## Anti-AI-slop additions

Reject generic hero copy, gradient orbs, equal feature-card grids, excessive rounded containers, default component-library styling, invented metrics, unexplained sparkle icons, and interchangeable layouts. If unrelated products could share the same screen without changing the structure, copy, and interaction model, make the design more specific.

## Quality bar

Preserve the existing designgood requirements for visual direction, semantic tokens, UX states, responsiveness, accessibility, motion, and 13/16 quality scoring. When `dsngood` is requested, use the stricter 16/20 handcrafted release gate and report the author’s note, source material, anti-slop changes, and remaining compromises.
